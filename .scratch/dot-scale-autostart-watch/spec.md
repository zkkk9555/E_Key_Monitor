# spec: dot-scale-autostart-watch

Status: ready-for-agent

## Problem

用户拿便携包到游戏机上用，反馈三件事：左边那个圆点太小；希望它在每块显示屏上占比一致、不受 Windows 缩放百分比影响；希望加一个开机自启开关，并且开��永劫无间时自动显示圆点、关掉游戏后自动隐藏——这样设好开机自启就再也不用管这个软件。

当前实现的三个缺口（已逐条定位）：

- `MainForm.cs:1643-1651` 圆点直径是**固定像素**（小 18 / 中 26 / 大 34），与屏幕尺寸、缩放比例都无关。实测：本机 2560x1600、150% 缩放（DPI 144）下窗口只有 40x40 **设备**像素，圆点 26 物理像素 ≈ 4.6mm；换到 100% 缩放的 1080p 屏，同样的 26 像素 ≈ 6.9mm。**同一份 EXE 在不同屏上物理大小差 1.5 倍**，这就是"比例不一致"的来源。
- 没有任何开机自启入口。
- `--follow-game` 模式下圆点**一直显示**，游戏退出后是**整个程序退出**（`MainForm.cs:1361-1365`）。用户要的是"圆点消失、程序留下"。

## Solution

三个切片：

1. 圆点按**屏幕设备像素高度的百分比**计算，并切到 Per-Monitor V2 DPI 感知，窗口尺寸由圆点推导（不再用固定 `windowSize`）。
2. 托盘新增「开机自启」勾选项，写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值 = 当前 EXE 绝对路径 + `--watch`。默认关闭，只有点开关才写。
3. 新增 `--watch` 常驻跟随模式：启动只留托盘；游戏进程出现才显示圆点；游戏消失连续 5 秒隐藏圆点，**程序不退出**。

## User Stories

1. 作为在多台不同分辨率、不同缩放的电脑上用这个工具的人，我希望圆点在每块屏上看起来一样大，以便我一换屏它不会变小或变得巨大。
2. 作为用 100% / 150% 缩放混用的人，我希望圆点不跟着 Windows 的缩放百分比一起变，以便它在两台电脑上观感一致。
3. 作为觉得圆点太小的人，我希望它明显变大，并且仍然能调节大小。
4. 作为不想每次手动开软件的人，我希望有一个开机自启开关（在软件里点一下），以便开机后它就自己在后台待命。
5. 作为只想在打游戏时才看到提示的人，我希望游戏开着时圆点出现、游戏关了圆点消失，但软件继续在托盘里等着下一次游戏。
6. 作为用户，我希望开机自启是**默认关闭**、我自己点一下才生效，并且随时能再点一下关掉。
7. 作为用户，我不希望这些改动影响现有的安全边界：工具仍然只观察，不碰输入。

## Implementation Decisions

- **尺寸模型**：圆点直径 = 当前所在屏幕**设备像素**高度的百分比——小 2.0%、中 3.0%、大 4.0%（默认中）。选百分比而不是固定毫米，因为用户要的是"每块屏上占比一致"。物理尺寸自然接近：1080p 24" 上 3% ≈ 32px ≈ 8.9mm；本机 1600px 高上 3% ≈ 48px ≈ 8.5mm。
- **DPI 感知从 SystemAware 改 PerMonitorV2**（`Program.cs:22`）。不改的话应用坐标被系统缩放，圆点会随缩放百分比变化，正好是用户不想要的。改后应用坐标 = 设备像素，百分比算法才成立。
- **窗口尺寸改为派生**：`ClientSize` = 圆点直径 + 2×边距(6px)，删除配置里的固定 `windowSize` 字段（`MainForm.cs:169-172`、DTO `:215-216`）。窗口尺寸必须跟着圆点走，否则大圆点会被裁掉。
- **WM_DPICHANGED**：圆点被拖到另一块屏、或系统改缩放时，按新 DPI 重算尺寸、重定位、重绘（`WndProc` 拦截 0x02E0）。
- **开机自启用 HKCU Run**：不需要管理员权限，不需要额外的安装器，天然是"当前用户 + 当前 EXE 路径"，且删掉注册表值就等于关闭。写成 `"<exe绝对路径>" --watch`，让开机启动的实例直接进入常驻跟随模式。
- **自启状态读真实注册表**，不另存配置：菜单勾选状态 = Run 键里那个值是否存在且指向当前 EXE；若值存在但路径已失效（便携包被挪走），菜单显示未勾选并提示重新生成。
- **默认关闭**：程序**绝不**自己写 Run 键，只有用户在托盘点「开机自启」才写。
- **`--watch` 与 `--follow-game` 并存**：`--follow-game` 保持"游戏结束程序退出"的既有语义（联合启动脚本在用），`--watch` 是新的"游戏结束只隐藏圆点"语义。**只有 `--watch` 不套用 10 分钟启动超时**（常驻模式要一直等）；`--follow-game` 保持旧语义，超时仍会提示并退出。
- **隐藏圆点用真正的 Hide()**，不是"画成全透明"：全透明窗口在关闭鼠标穿透后仍会吃掉点击。

## Testing Decisions

- **seam 1（视觉）**：启动 EXE → 截屏 → 在预期位置量圆点像素直径 → 与"屏幕高度 × 百分比"的期望值比对。改前 26px，改后应等于屏幕高度的 3%。红→绿可判。
- **seam 2（常驻跟随）**：用一个**进程名**为 `NarakaBladepoint` 的替身进程（把 `ping.exe` 复制改名，不启动真游戏）→ 断言圆点出现；杀掉它 → 断言圆点消失、**进程仍在**。
- **seam 3（自启）**：读 `HKCU\...\Run\E_Key_Monitor`：默认不存在；调用开关后存在且内容 = EXE 路径 + `--watch`；再调用一次即删除。
- **构建门**：`dotnet build -c Release` 0 警告 0 错误；`dotnet format --verify-no-changes` 通过；PS 5.1 解析 0 错。
- **约定门**：`tools\verify-conventions.ps1` 保持全绿（配置字段数从 10 变 9，校验器同步更新）。
- **不测的**：不启动真游戏（本机 15.7GB 内存只剩 0.8GB，跑不动）；不验证开机自启在真实重启后生效；不验证多显示器热插拔。

## Slices

- [x] **S1 圆点按屏幕比例 + Per-Monitor V2**：直径 = 屏幕设备像素高度的 2/3/4%；窗口尺寸由圆点推导；`WM_DPICHANGED` / 拖动 / 换预设都会重算。实测：本机 2560x1600 屏 3% = 48 设备像素（改前固定 26）。
- [x] **S2 开机自启开关**：托盘勾选项 → `HKCU\...\Run\E_Key_Monitor` = `"<EXE>" --watch`；默认关闭；菜单状态读真实注册表；失效路径会被替换而不是被误判为「已开启」。
- [x] **S3 常驻跟随 `--watch`**：启动只留托盘 → 游戏进程出现才显示圆点 → 游戏消失约 5 秒后隐藏圆点、程序留在托盘。实测用进程名替身驱动，行为符合。

## Out of Scope

- 不动安全边界：不模拟输入、不拦截输入、不加鼠标 Hook、不碰游戏内存。
- 不改语言栈、不加第三方 NuGet 包（注册表用 `Microsoft.Win32.Registry`，属 BCL）。
- 不做额外的常驻通知/气泡 UI（自启开关点击后的结果提示沿用既有的托盘气泡，不新增常驻提示）。
- 不做"开机自启延迟启动""以管理员身份启动"等变体。
- 不启动真实游戏进程做联调。

## Glossary

- **设备像素**：屏幕真实的物理像素，Per-Monitor V2 下应用坐标即设备像素。
- **逻辑像素**：Windows 按缩放百分比虚拟化后的坐标，用户看到的大小。
- **常驻跟随（`--watch`）**：程序常驻托盘，只在游戏运行时显示圆点。

## Further Notes

### 设计树（自答，用户 AFK）

- **Q1 圆点按什么缩放？** 固定像素（现状）→ 固定毫米 → 屏幕百分比。用户原话是"每个显示屏上对应的比例大小都要是一致的"，取百分比；顺带让物理尺寸也接近（8.5–8.9mm）。
- **Q2 要不要接受 Windows 缩放？** 要接受感知、但不让它改变观感：PerMonitorV2 感知 + 百分比算法 ⇒ 缩放百分比只影响坐标换算，不影响圆点占屏比例。
- **Q3 自启写哪？** HKCU Run（无需管理员、可逆、指向便携 EXE）。不做任务计划、启动文件夹、HKLM。
- **Q4 自启默认开还是关？** 关。程序不自己写注册表，用户点开关才写。
- **Q5 新模式还是改旧模式？** 新增 `--watch`，保留 `--follow-game` 语义（联合启动脚本在用），避免把既有行为改回去。
- **Q6 隐藏圆点用 Hide 还是画透明？** Hide。透明窗口在关闭穿透后仍吃点击。
