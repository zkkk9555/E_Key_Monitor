# 中文入口与说明书设计

> 历史方案：本文件记录的 BAT 包装器方案已被 `2026-07-24-single-exe-portable-launch-design.md` 取代；保留此文件作为历史设计记录。

## 背景

项目已有可用的英文命名脚本，但用户难以从文件名判断每个入口的用途。现有联合启动和桌面快捷方式逻辑已经能够完成监控工具与原始游戏启动器的协同启动，因此只需要增加易懂的中文外层入口和说明，不需要重写启动逻辑。

## 方案

保留英文脚本作为内部实现层，新增中文文件名的 BAT 包装器：独立启动监控、正式联合启动、开发联合启动、生成桌面入口、制作便携版。每个包装器只调用同目录既有 PS1，BAT 文件内容保持纯 ASCII，以符合现有兼容规则。

桌面快捷方式生成脚本继续创建两个快捷方式，但目标改为中文 BAT 包装器：

- `E键监控工具.lnk`：独立启动监控工具。
- `永劫无间（E键提示）.lnk`：启动监控工具后启动原始 `StartGame.exe`。

根目录默认配置写入用户给出的游戏目录。运行目录中的配置仍由程序旁边的 `config.json` 决定；如果项目移动或已经存在旧发布目录，需要重新构建或在工具菜单中重新选择目录。

## 用户流程

```text
中文 BAT 入口
    -> 现有英文 PS1 实现
    -> 监控 EXE / dotnet run / 原始 StartGame.exe
```

说明书用中文解释入口用途和内部脚本的关系，并明确区分正式启动、开发启动、打包和桌面入口生成，避免用户误把计划或内部脚本当作日常入口。

## 错误处理与边界

沿用现有脚本的路径、配置和 EXE 校验。中文包装器不绕过检查、不硬编码旧项目路径、不直接启动游戏本体；游戏目录只作为默认配置写入，不涉及读取敏感信息。

## 验收标准

- 资源管理器中可看到中文入口文件名，双击后仍进入既有脚本流程。
- 生成的两个桌面快捷方式目标为当前项目的中文入口，不再依赖旧用户目录。
- 说明书覆盖每个中文入口和日常使用步骤。
- 构建、格式检查和静态脚本检查通过；没有 C# 源代码改动。
