# 圆点按屏幕比例定尺寸，开机自启用当前用户 Run 键

Status: accepted

两件事一起定下来：圆点的直径是**屏幕设备像素高度的百分比**（小 2% / 中 3% / 大 4%），程序切到 Per-Monitor V2 DPI 感知；开机自启写在当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值是当前 EXE 路径加 `--watch`，**默认关闭**。

## Considered Options

- 圆点用固定像素——被否：同一份 EXE 在 150% 缩放的 2560x1600 屏上是 26 物理像素（约 4.6mm），在 100% 缩放的 1080p 屏上同样是 26 物理像素（约 6.9mm），**跨屏物理大小差 1.5 倍**，这正是用户要解决的问题。
- 圆点用固定毫米——被否：物理大小处处一致，但在更大的屏上占比会明显变小，观感不一致。
- 保持 SystemAware——被否：坐标被系统按缩放百分比虚拟化，圆点会随缩放百分比一起变大；改成 Per-Monitor V2 后坐标就是设备像素，百分比才有意义。
- 开机自启用任务计划 / 启动文件夹 / HKLM——被否：任务计划要多一个常驻任务且要管理员；启动文件夹会塞进用户的“启动”目录、用户看不出是哪个程序；HKLM 要管理员权限。HKCU Run 无需管理员、删除即完全可逆。
- 开机自启默认打开——被否：程序擅自改系统启动行为越界；改成默认关闭、由用户在托盘点一次开关。

## Consequences

- 配置里的 `windowSize` 字段被删除：窗口尺寸由圆点直径推导，留着它就会和圆点打架。旧配置文件里的这个字段会被忽略。
- `--watch` 让程序常驻托盘、只在游戏运行时显示圆点；`--follow-game` 保持"游戏结束程序退出"的旧语义不变，联合启动脚本不受影响。
- 便携文件夹一旦移动，注册表里的旧路径就失效：托盘菜单会显示未勾选，重新开一次开关即可指向新路径。
- 圆点尺寸现在依赖屏幕分辨率，截图/目测的绝对像素数会随屏幕变化——判断标准要改成"占屏百分比"。
